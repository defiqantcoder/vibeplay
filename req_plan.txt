I have investigated `src/vibeplay/web.py` and `src/vibeplay/routers/`.

The `create_app` function in `web.py` is nearly 2000 lines long. It defines over 50 nested FastAPI route handlers (e.g. `api_play_track`, `api_get_settings`, `api_dsp_peq_presets`).

Some routers like `src/vibeplay/routers/player.py` and `src/vibeplay/routers/settings.py` exist but:
1. `player.py` only implements a few player routes (leaving 10+ still inside `web.py`'s `create_app`).
2. `settings.py` implements the settings endpoints, but those same endpoints are ALSO still defined in `web.py` (duplicate code). And `settings_router` is never actually included in `create_app`.

My plan is:
1. Initialize the FastAPI `app.state` inside `create_app` with variables required by routes, e.g., `db_path`, `settings`, `templates`.
2. Extract all remaining nested routes from `create_app` into their corresponding APIRouter modules:
   - Move all remaining `/api/player/` routes to `routers/player.py`.
   - Remove the duplicate `/api/settings/` endpoints in `web.py`, as they already exist in `routers/settings.py`.
   - Create new routers for the other endpoints (e.g., `routers/playlist.py`, `routers/dsp.py`, `routers/desktop.py`, `routers/library.py`, etc.).
   - Make sure they use `request.app.state` to access `db_path`, `settings`, and `templates` where applicable.
3. Import and mount all these routers using `app.include_router(...)` in `web.py`.
4. Ensure the pre-commit checks pass and the codebase is clean.
